# ZONA Z — реальный рейтинг Telegram (черновое обновление)

Эта ветка **не опубликована**: основная игра в `main` пока не изменена.
Файлы игры: `index.html`, `online-config.js`, `online.js`.
Сервер: папка `backend/`. Публичный GitHub Pages **не запускает Node.js и PostgreSQL**.

## Как включить позже (только после тестов)

1. Создать PostgreSQL и отдельный веб-сервис Node.js у хостинг-провайдера (например, Render). Веб-сервис настраивается из **этого репозитория**, root directory: `backend`, build: `npm install`, start: `npm start`.
2. На сервере задать приватные переменные `BOT_TOKEN` (из BotFather), `DATABASE_URL` (строка PostgreSQL), `ALLOWED_ORIGINS=https://elyxiumcoin.github.io`, `NODE_ENV=production`. Не добавлять реальные значения в GitHub и не присылать токен в чат.
3. Убедиться, что `https://АДРЕС_СЕРВЕРА/api/health` показывает `{"ok":true}`.
4. В `online-config.js` указать адрес сервера по HTTPS, **без /api и завершающего слэша**.
5. Открыть существующий Telegram Mini App на прежнем адресе GitHub Pages. При первом обнаружении локального прогресса игрок должен **сам нажать «Да, перенести мой прогресс»** во вкладке «Рейтинг»; без этого данные не отправляются. Проверить на двух тестовых учётных записях восстановление после перезапуска и появления в рейтинге.
6. Только после тестов одобрять PR в `main`. Адрес игры у Telegram-бота не менять.

## Гарантии и ограничения

- Сохранения основной игры сейчас хранятся в браузере в `localStorage` (ключ `zona_z_save_v10`, с чтением v9/v5). Сам GitHub **не содержит сохранений всех игроков**.
- Первый перенос локального сохранения требует явного подтверждения владельца Telegram-аккаунта; отказ не удаляет данные.
- Перед первой синхронизацией создаётся отдельная резервная копия. Если создать копию невозможно (например, из-за переполнения хранилища), перенос останавливается.
- При конфликте облачного и локального прогресса игрок **выбирает сам**, какой вариант оставить. Никогда не надо удалять localStorage, менять домен Mini App или заставлять игроков переустанавливать Telegram.
- Сохранения старых игроков можно перенести только после их входа с устройства, где эти сохранения всё ещё доступны. Если Telegram уже очистил браузерное хранилище, код не сможет восстановить отсутствующие данные.
- Telegram ID проверяется сервером через HMAC подпись `initData`. Пользователи без подтверждённого входа не попадают в общий рейтинг.
- Пока игровые награды начисляются на стороне браузера, клиентскую статистику можно подделать. Это **рейтинг проверенных Telegram-аккаунтов**, но не полностью защищённый от читерства.
- Сервер следует держать за HTTPS и не размещать `BOT_TOKEN` в HTML, `online-config.js` или публичных файлах.
- Для проверки синтаксиса и подписи: `cd backend && npm install && npm run check` (в том числе тесты ручного подтверждения переноса и конфликтов). Доступ к настоящей PostgreSQL и тестовый Telegram-бот нужны для интеграционного теста, они не предоставлены.

## Принцип работы

Браузерное сохранение → проверка Telegram подписи → API `/api/me`, `/api/save` с номером ревизии (ошибка 409 при конфликте) → PostgreSQL → `/api/leaderboard`.
Список «ботов-сталкеров» в старой вкладке заменяется на реальные строки из базы.

### Важный сценарий для владельцев старого прогресса

У игрока может быть старый персонаж в браузерном хранилище GitHub Pages и иной тестовый персонаж в Neon под **тем же Telegram ID**. Такие данные нельзя сливать автоматически. Игроку должны быть показаны оба персонажа и три действия:

1. «Загрузить облачное»: явно заменяет местное сохранение, предварительно сохраняя местную резервную копию.
2. «Перенести местное в облако»: явно перезаписывает облачную версию сохранением с текущего устройства, после сохранения резервной копии местного прогресса.
3. «Пока ничего не менять»: ничего не отправляет и не заменяет.

Проверка до публикации: два реальных Telegram-аккаунта, длительный прогресс, отключённая сеть, повторный вход, совпадение ревизий, восстановление после конфликта. Не менять Telegram Menu URL и origin сайта GitHub Pages. Не просить пользователей очищать кэш приложения.

### Восстановление в случае неудачного обновления

Сначала остановить развёртывание нового фронтенда, вернуть ветку `main` к проверенному commit из `backup/zona-z-before-online-2026-10-21` через согласованный GitHub PR или revert, не сбрасывая и не удаляя пользовательские `localStorage`. Возвращение кода само по себе **не восстанавливает** уже потерянные браузерные данные. Синхронизация Neon должна быть остановлена/заморожена до выяснения конфликтов.
